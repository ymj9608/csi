# 프런트엔드 팀 전달: 아키텍처에서 수집할 정보

목적은 **구조 이미지 → 관련 서비스와 개인정보 흐름 → 실제 코드 경로 → 제한된 수정안 입력**을 연결하는 것입니다. 이미지만으로 전체 코드를 이해했다거나 보안 문제를 확정했다고 표시하지 않습니다. 사용자가 제공한 “무엇을 저장할지” 표의 구조·역할·업무 흐름·출처·버전·보안 속성·검토 상태에 **개인정보 처리 종류와 코드 연결 정보**를 더합니다.

아래 표는 목표 수집 계약입니다. 현재 구현된 v1의 범위와 후속 v2 항목은 문서 하단에 구분했습니다.

## 누가 무엇을 입력하나

1. 사용자는 프로젝트·이미지·그림 종류·기준 커밋을 지정하고, 필요한 업무 설명과 구성요소↔모듈 매핑을 보완합니다. 이미지 종류를 모르겠으면 AI 분류 후 확인할 수 있습니다.
2. 서버는 이미지 해시·원본 크기·업로드 시각·업로더·버전·모델/프롬프트 식별자를 기록합니다. 이런 값은 모델에게 추측시키지 않습니다.
3. AI는 보이는 요소·연결·역할·문구를 추출하고, 해석과 미확인 사항을 분리합니다. 코드 인덱스가 경로 존재·심볼·참조를 확인합니다.
4. 사람은 업무 목적·개인정보 종류·그림의 최신성·모듈 매핑을 확인합니다. 사람이 수정한 값도 원래 추출값과 이력으로 구별합니다.

## 저장할 정보와 판정 기준

| 항목 | 값 | AI가 할 일 / 확인 기준 |
|---|---|---|
| 원본·버전 | projectId, 원본 이미지, SHA256, width/height, 기준 commit, model/prompt/schema version, 작성·수정 시각 | 서버 생성. 같은 그림이라도 변경 커밋과 맞는지 별도 확인 |
| 노드 | 안정적인 elementId, 원문 label, 역할, 기술 스택·명시된 버전, 소속 groupId | 이름·역할 추출. 로고로 제품을 추정하면 추정이라고 표시 |
| 엣지 | elementId, sourceId, targetId, 방향, 원문 label, 통신 방식, 전달 데이터 | 화살표와 원문 근거를 연결. 방향 불분명하면 확인 불가 |
| 그룹·경계 | groupId, 상위 그룹, 명칭, 내부/외부/알 수 없음 | 단순한 사각형 그룹을 자동으로 신뢰 경계로 단정하지 않음 |
| 업무 흐름 | flowId, 업무명, 순서 있는 노드·엣지 경로, 시작 조건, 처리 목적 | 예: 회원가입→검증→저장→알림. 그림에서 생략된 순서를 만들어내지 않음 |
| 개인정보 | 전화번호·이메일 등 필드/종류, 수집·조회·변환·저장·로그·전송·삭제 작업, 관련 노드/엣지 | **실제 개인정보 값은 수집하지 않음**. 종류·처리 목적이 불명확하면 사람에게 확인 |
| 처리 조건 | 보관·삭제 기준, 외부 수신자·처리 위치, 접근 가능한 역할 | 그림·업무 설명·설정에 근거가 있을 때만 기록. 빈 값은 `알 수 없음`이며 보관 기한이나 적법성을 AI가 만들어내지 않음 |
| 보안 속성 | 외부 노출, 호출 주체, 인증·인가, 전송/저장 보호, 민감정보 로그 여부 | `확인됨/추정/확인 불가`와 출처 함께. 그림의 미표시를 미적용으로 처리하지 않음 |
| 코드 연결 | repository, commit, module/directory, 파일·클래스·메서드, 연결 이유·검증 상태 | 그림의 경로 힌트와 manifest로 확인된 실제 경로를 분리. API→서비스→DTO→저장소→스키마→로그/외부 전송 경로를 찾음 |
| 출처 | 원본 imageVersionId, 요소 bbox, 읽은 원문, 코드/설정/정책 근거 ID | UI에서 원본 위치와 확인 근거로 돌아갈 수 있도록 저장 |
| 검토 | 관찰/추정/확인 불가, 제한 사항, 미검토/확인/수정/반려, 검토자·시각·수정 사유 | 모델 confidence 숫자를 교정된 정확도처럼 표시하지 않음. 실제 확인 주체와 근거를 우선 |

권장 bbox 규약은 **업로드 원본의 좌상단 기준 `(x, y, width, height)`를 각각 0~1로 정규화**한 값입니다. 원본 width/height와 전처리 방향을 함께 보존해야 합니다. 좌표를 확인하지 못하면 null로 두며 추정 위치를 정밀한 좌표로 위장하지 않습니다. 크롭·회전·리사이즈를 했다면 원본으로의 변환 정보도 필요합니다.

관찰·추정·확인 불가와 출처는 **각 속성 단위**로 붙입니다. 예를 들어 `PostgreSQL`이라는 이름은 그림에서 관찰했더라도 저장 암호화 적용 여부는 확인 불가일 수 있습니다. 버전 간 같은 노드인지 불확실하면 새 요소로 남기고 임의로 ID를 합치지 않습니다.

### AI가 반환해야 할 판단 결과

1. **구조 해석:** 그림 종류, 구성요소의 역할, 연결·데이터 이동, 그림으로 확인 가능한 범위.
2. **점검 우선순위:** 어떤 개인정보가 어디를 지나며 저장·로그·외부 전달 지점을 먼저 확인할지, 그 이유.
3. **코드 탐색 계획:** 실제 manifest와 연결된 모듈·파일 후보, 필수 스캐너 근거, 추가로 읽어야 할 관련 경로.
4. **확인 필요 사항:** 모듈 매핑 실패, 오래된 그림, 누락된 배치·외부 서비스, 판단에 필요한 사용자 설명.

후속 연동 시 이 네 가지를 코드 리뷰 Agent에 전달할 계획입니다. 위험 등급·정책 위반·수정안은 이후 실제 코드와 설정·정책 근거를 확인한 단계에서 결정합니다. 그림에 TLS나 암호화 표시가 없다는 이유만으로 `미적용` 또는 `위반`으로 표시하지 않습니다.

## 전화번호 사례

사용자 입력: “전화번호가 포함된 회원 정보를 처리하며, 로그 노출을 보완하려고 한다.”

AI/코드 인덱스의 결과는 다음 항목이어야 합니다.

- **처리 경로:** 전화번호 입력 API → DTO 검증/변환 → 서비스 → 저장소·DB 컬럼 → 로그·알림·외부 전달. 실제로 확인된 경로와 미확인 연결을 구분합니다.
- **검토 파일:** Controller, 요청/응답 DTO, Service, Repository/Mapper, Entity·schema/migration, logging·masking helper, 관련 테스트. Spring Boot/PostgreSQL이라는 기술명만으로 파일을 선정하지 않습니다.
- **변경 범위:** 로그 마스킹 문제라면 전화번호 저장·인증 계약을 임의 변경하지 않고 로그 출력과 연결 테스트를 검토합니다. 저장 보호 문제라면 읽기·쓰기·조회·키 설정·기존 데이터 전환까지 확인할 추가 범위를 표시합니다.
- **근거:** 이 코드가 전화번호를 처리한다는 원문 행, 호출 관계와 해당 사내 정책. 아키텍처는 파일 탐색 근거이며 보안 위반 확정 근거가 아닙니다.
- **불확실성:** 외부 로그 수집기·배치·다른 서비스·실제 배포 설정을 확인하지 못했는지 표시합니다. 도면 밖 경로는 전체 스캐너 결과와 변경 파일로 보완합니다.

## 현재 API와 추가해야 할 계약을 구분

**현재 구현된 v1:** 프로젝트 이미지·해시·버전·업로더·기준 커밋, `diagramType`, `components[{id,label,kind}]`, `flows[{from,to,data,protection}]`, `trustBoundaries[]`, `codeHints[]`, `assumptions[]`, `uncertainties[]`, `summary`, 측정 `metrics` 및 작업 상태.

**후속 v2 설계 대상:** groupId·그룹 계층, 엣지 ID, 순서 있는 업무 흐름, 개인정보 처리 항목 구조체, 요소별 bbox·출처, 요소별 검토 이력, 사용자 확인 API, manifest 검증된 코드 매핑 구조체. 현재 v1은 알 수 없는 필드를 거절하므로 프런트엔드가 이 필드를 임의로 추가해서 보내면 안 됩니다. v1 기본 연결 뒤 백엔드·worker·TypeScript 계약을 함께 버전업해야 합니다.

**프런트 MVP 필수 입력:** 프로젝트, PNG/JPEG 이미지. 기준 커밋은 선택 입력이며 미지정 시 최신성은 `UNKNOWN`입니다. 권장 추가 입력은 업무 목적 설명·그림 종류·주요 개인정보 종류·구성요소↔저장소 모듈 매핑입니다. 추가 입력의 저장 API는 v2에서 함께 합의합니다. 원본 전화번호·이메일·비밀번호·운영 비밀값을 입력 폼에 요구하지 마세요.

연동 함수는 `frontend/src/lib/architecture.ts`, 정확한 v1 요청/응답은 [API 계약](ARCHITECTURE_API.md)을 사용합니다. `READY`는 “이미지 해석 완료·코드 확인 필요”입니다. “전체 구조 검증 완료”나 “개인정보보호법 준수 확인”으로 표시하지 않습니다.
