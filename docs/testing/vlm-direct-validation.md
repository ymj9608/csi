# VLM 직접 위임 경로 검증

> 이 문서는 이전 Qwen `vlm-direct-v1` 구현의 역사적 실측 기록입니다. 이후 `scripts/smoke_vlm_coding.py`의 기본 경로가 **OpenAI API 총괄**로 바뀌었으므로 아래 과거 명령을 현재 버전에서 실행하면 같은 실험이 아니며 외부 전송·과금이 발생합니다. 현재 동작과 검증은 [OpenAI 총괄 검증](vlm-orchestrator-validation.md)을 참고하세요.

검증일: 2026-10-23. 범위는 Qwen3-VL의 자연어 작업 지시 → Ministral 코드 생성 → 기존 격리 검증입니다. 비전 도입의 정확도·비용 우월성을 비교하는 벤치마크가 아닙니다.

## 구현 계약

- 새 수정안은 프로젝트에서 선택한 원본 이미지 버전을 고정합니다. 나중에 연결 이미지를 바꿔도 queued 작업의 이미지가 바뀌지 않습니다.
- 정책, 기존 AI 분석, RAG 인용과 고정 커밋의 소스를 Qwen에 전달합니다. 이미지 구조 JSON을 만들거나 읽지 않습니다.
- VLM 최종 자연어 지시문을 코딩 모델에 직접 전달합니다. 토큰/시간/이미지 해시와 지시문은 결과에 기록합니다.
- VLM 실패·잘림·근거 누락 시 코드 생성은 중단됩니다. 수정 범위, 보안 검사, 관리자 승인 조건은 유지됩니다.
- 수정 가능한 파일은 `backend/app/core/csi_signup.py` 하나입니다. `hub.py`·`dto.py`는 회원가입/로그인 관련 선언만 읽기 전용 맥락으로 전달합니다.

Python과 UI 테스트의 모델/HTTP 응답은 모의 데이터입니다. PostgreSQL 테스트는 임시 `postgres:17-alpine` 컨테이너·무작위 스키마를 사용하고 종료 후 제거했습니다. 운영 DB는 변경하지 않았습니다. Mockito는 실행 환경의 자동 attach 제한을 피하기 위해 명시적 Java agent로 실행했습니다.

## 실모델 점검 데이터와 재현

```sh
.venv/bin/python scripts/smoke_vlm_coding.py --repo ../Lichu
```

- 실제 코드: Lichu 커밋 `95345dbd8ba45fe77ea8cd926c84e40e4d16f83a`의 Git blob.
- 이미지: `docs/benchmarks/lichu-architecture.png`. 이전에 코드를 기준으로 작성한 도식이며 독립된 운영 설계 문서는 아닙니다.
- 근거: `rag/catalog.json`의 POL-04/POL-05, `rag/policy.json`의 가상 실습 정책.
- 위험 ID: 명시적인 테스트용 `smoke-SEC-02/03/05`. 실제 백엔드 검사 작업이나 실제 RAG 검색 호출은 아닙니다.
- 모델: 로컬 `qwen3-vl:8b`와 `ministral-3:8b-instruct-2512-q4_K_M`.
- 코드 검증: 네트워크가 차단된 기존 Docker 검증기와 SQLite. 원본 저장소 적용·승인·배포 없음.
- 재현 출력: `.runtime/vlm-direct-smoke/summary.json`. 응답/후보 코드는 같은 디렉터리의 0600 파일에 보관하며 Git에 포함하지 않습니다.

초기 점검에서 전체 관련 파일 입력은 180초 제한을 넘겼습니다. 관련 선언만 남겨 입력을 줄인 시도는 출력 1,200토큰에서 최종 지시문 전에 잘려 차단됐습니다. 출력 한도를 3,000토큰으로 늘린 시도도 최종 지시문 전에 잘렸습니다. 최종 구현은 assistant prefill로 추론 구간을 닫고 자연어 최종 답변 구간을 열어 이어 쓰게 합니다. 짧은 호환성 점검에서 thinking 길이 0, 정상 stop 응답을 확인했습니다. 최종 설정은 12,288 컨텍스트·최대 출력 1,600토큰·240초입니다. 테스트 스크립트에도 같은 240초 제한을 적용했습니다. 이 설정이 모든 Mac과 입력에서 시간 내 완료를 보장하지는 않습니다.

실제 자연어 응답에서 문서 섹션 번호만 인용하고 근거 chunk ID를 누락한 시도는 `VLM_EVIDENCE_MISSING`으로 차단했습니다. 프롬프트의 첫 줄에 정확한 인용 문자열을 복사하도록 명시하고, 잘못된 bcrypt 접두사 추가·미정의 로그 변수 권고도 금지하도록 보완했습니다.

첫 코드 생성에서 READY에 도달했습니다. 총 123.394초, VLM 지시 생성 54.535초, Ministral 생성 50.358초, 수정 후 Docker 검증 11.484초였습니다. VLM 입력 5,447토큰·출력 590토큰이며 thinking 텍스트 길이 0을 확인했습니다. 코딩 모델의 토큰 수는 기존 엔진이 집계하지 않으므로 전체 추론 토큰 합계는 제시하지 않습니다.

이것은 위 단일 실습 커밋의 성공 사례입니다. 원본 코드는 변경하지 않았고, 실제 서비스의 백엔드 작업 등록·결과 전송을 포함한 통합 시연은 실행하지 않았습니다. 그 경로는 별도의 PostgreSQL/HTTP 모의 테스트로 검증했습니다. SQLite 검사에서 동시성 테스트 1개는 건너뛰었으며 전체 서비스 보안·법률 준수나 범용 코드 수정 성능을 보증하지 않습니다.

[실측 및 자동 검증 요약 JSON](vlm-direct-smoke.json)에 초기 실패와 최종 성공을 함께 기록했습니다. 이전 아키텍처 비교 실험 로그는 변경하지 않았습니다.
