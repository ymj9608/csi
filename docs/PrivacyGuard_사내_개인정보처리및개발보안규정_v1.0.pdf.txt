POL-03 PR 변경 감지와 Privacy Policy Drift 검사
개인정보 처리 코드가 변경되면 사용자 수동 요청 없이 PR 생성·수정 이벤트를 통해 자동 검사를 요청합니다.
POL-03.1 | 트리거: GitHub Pull Request의 생성(opened), 코드 동기화(synchronize), 재개(reopened) 이벤트를 대상으로
합니다. 정적 분석 엔진은 검사 시점의 고정 Commit SHA에 대응하는 읽기 전용 스냅샷을 분석합니다.
POL-03.2 | 변경 검토 대상: SignupRequest, User, Account, Auth, PasswordEncoder, Security, Logger, Repository 및
개인정보 필드·보유기간·처리 목적과 관계된 정책 파일의 수정. 파일명은 힌트일 뿐이고 검사 범위를 파일명에만 의존하지 않습니다.
POL-03.3 | 신규 필드 탐지: 데이터 인벤토리(POL-02)에 없는 필드가 DTO/Entity에 추가되면 REVIEW로 분류합니다. 실제 저
장·전송 경로와 승인 부재가 확인된 경우에만 내부 정책 FAIL을 검토합니다.

POL-04 비밀번호 저장 및 인증 보안
원문 비밀번호의 저장·기록을 금지하고, 승인된 느린 비밀번호 전용 해시 알고리즘만 사용합니다.
POL-04.1 | 신규 기능 기본값은 Argon2id를 권장하며, Spring Security의 BCryptPasswordEncoder 사용도 허용합니다.
bcrypt 사용 시 Work Factor는 최소 12로 정합니다(사내 강화 기준; OWASP 일반 권고 최소 10과 구분).
POL-04.2 | Argon2id는 최소 m=19 MiB, t=2, p=1 또는 CPO가 승인한 상향 설정을 사용합니다(OWASP 가이드 참고). 대상 런
타임에서 인증 성능을 시험한 뒤 설정을 확정합니다.
POL-04.3 | 원문 비밀번호에 MD5, SHA-1, SHA-256 등 빠른 범용 해시를 단독 적용하여 DB에 저장해서는 안 됩니다. 사용자별
고유 Salt를 사용하는 라이브러리 표준 기능을 우선 사용합니다.
POL-04.4 | 고정 Salt, 코드에 하드코딩된 Salt, 자체 설계한 암호식은 사용 금지입니다. 비밀번호를 복원이 가능한 형태로 암호화하
여 저장하는 설계는 허용하지 않습니다.
POL-04.5 | bcrypt의 일반적인 72바이트 입력 처리 한계를 검토하고 보안팀과 입력 정책을 합의합니다. 알고리즘·Work Factor
변경은 이관/재해시 계획을 포함합니다.
Spring Boot 코드 예시 (설명용)
// Approved example for legacy-compatible Spring Security
PasswordEncoder encoder = new BCryptPasswordEncoder(12);
String passwordHash = encoder.encode(rawPassword);
userRepository.save(new User(email, passwordHash));
문서 예시는 코드의 핵심 구간만 표현합니다. 실제 보안 판정 시 호출 경로와 설정값을 함께 확인하십시오.

POL-05 로그 및 민감정보 보호
운영 로그에 계정 인증 비밀 및 개인정보 원문을 기록하지 않는 것을 기본값으로 합니다.
POL-05.1 | 절대 금지: raw password, 전체 Authorization 헤더, Access/Refresh Token 원문, Session ID 원문, DB 비밀번
호, Encryption Key, 주민등록번호 원문.
POL-05.2 | 이메일·전화번호·이름 등 개인정보는 필요성 검토와 마스킹 없는 운영 로그 기록을 금지합니다. 디버깅을 이유로 요청/
응답 객체 전체를 기록하지 않습니다.
POL-05.3 | 권장 이벤트 스키마: timestamp, service, trace_id, request_id, event_type, status, severity,
actor_pseudonymous_id, policy_version, finding_id. 비밀값을 포함하지 않는 식별자를 사용합니다.
POL-05.4 | 로그 접근은 SECURITY_REVIEWER 또는 승인된 운영자에게만 허용하고 조회 행위를 감사 로그로 기록합니다.
잘못된 예
허용되는 대안
log.info("signup=" + request)
event=SIGNUP_STARTED, request_id와 상태만 기록
log.error("password=" + password)
event=AUTH_FAILURE, error_code만 기록
log.debug("token=" + accessToken)
event=TOKEN_ISSUED, trace_id만 기록
log.info("email=" + email)
event=NOTIFY_ATTEMPT, actor_pseudonymous_id 사용
POL-06 개인정보 저장·암호화·보유·파기
비밀번호 해시와 일반 개인정보의 복원 가능한 암호화를 혼동하지 않으며, 각 데이터 항목의 목적·보유 기간을 관리합니다.
POL-06.1 | 전송 구간은 HTTPS/TLS 등 인증된 보안 채널을 사용합니다. 개인정보 저장 시 암호화 적용 범위는 법적 의무, 처리 위
험도, 사내 승인 기준에 따라 정합니다.
POL-06.2 | 이메일 등 업무상 복원이 필요한 개인정보에는 적절한 암호화와 접근통제를 검토합니다. SHA-256 단독 해시가 암호화
의 대체 수단이 되는 것은 아닙니다.
POL-06.3 | 계정정보는 이용 목적이 종료되거나 탈퇴 처리 완료 후 불필요해지면 지체 없이 삭제합니다. 다른 법령의 보존 의무가 있
는 경우 해당 자료를 분리 저장하고 만료 후 파기합니다.
POL-06.4 | 실제 보존기간은 데이터 인벤토리와 외부 개인정보 처리방침에 구체적으로 명시합니다. 데모 데이터는 가상 정보만 사
용하며 실제 주민등록번호·비밀번호를 사용하지 않습니다.
POL-06.5 | 운영 이벤트 로그는 사내 기본 보존 90일로 설정하되, 법정 접속기록 및 조사·분쟁 증빙 등 별도 의무에 해당하는 기록에
는 해당 법적 기준을 우선 적용합니다. “90일”은 법정 접속기록의 보존기간을 뜻하지 않습니다.

POL-08 보안 검사 Agent, MCP, Sandbox 안전 수칙
Agent가 검사 대상 소스코드의 지시문을 명령으로 해석하지 않도록 입력과 실행 권한을 통제합니다.
POL-08.1 | 검사는 프로젝트 소유자가 승인한 Repository 및 Commit SHA에만 실행합니다. 경로 순회, 심볼릭 링크 탈출, 과도한
 파일 크기, 비허용 확장자는 차단합니다.
POL-08.2 | 정적 분석이 기본이며 검사 대상 코드를 직접 실행하지 않습니다. 동적 테스트가 필요한 별도 작업은 네트워크·파일 시
