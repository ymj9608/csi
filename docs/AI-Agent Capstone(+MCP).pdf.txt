계산기Server 만들기
1. MCP 기본구조
㖇mcp.tool 데코레이터가일반파이썬함수를Client가호출할수있는Tool로등록한다. 함수이름은도구이름, 인자타입은인자
스키마, docstring은도구설명이된다.
예제1㎿1  server.py
from fastmcp import FastMCP        # MCP Server를만드는클래스
# 1. Server 객체를만든다. 인자"Calculator"는Server 이름이다
mcp = FastMCP("Calculator")
# 2. @mcp.tool 데코레이터가일반파이썬함수를MCP 도구로등록한다
#    함수이름→ name, 인자타입→ inputSchema, 반환타입→ outputSchema
#    docstring → description. 모델이도구를선택할때읽는다
@mcp.tool
def add(a: int, b: int) -> int:
"""두숫자를더한다."""
return a + b                   # 반환값은structuredContent의result로전달된다
# 3. 직접실행할때만동작한다. 인자없는run()은stdio로요청을기다린다
if __name__ == "__main__":
mcp.run(show_banner=False)     # 시작할때출력하는배너를표시하지않는다
알아두기
이파일은직접실행하지않아도된다. client.py가이파일을하위프로세스로실행하고, 표준입출력으로연결한다.

{
"name": "add",                        # 함수이름
"title": "Add",                       # 이름에서자동으로만든표시용제목
"description": "두숫자를더한다.",    # docstring
"inputSchema": {                      # 인자타입힌트→ JSON Schema
"type": "object",
"properties": {"a": {"type": "integer"}, "b": {"type": "integer"}},
"required": ["a", "b"],             # 기본값이없는인자
"additionalProperties": false

MCP 메시지는JSON㎿RPC 2.0 형식이다. 요청에는id와method가있고, 응답은같은id로돌아온다. stdio에서는JSON 하나

예제1㎿5  1단계실행중stdio 기록㏙㏇meta 생략㏚
# ①연결(async with)
C→S {"jsonrpc":"2.0","id":1,"method":"server/discover"}
S→C {"jsonrpc":"2.0","id":1,"result":{"supportedVersions":["2026-07-28"],
"capabilities":{"tools":{},"resources":{},"prompts":{},"logging":{}}}}
# ②도구목록(list_tools)
C→S {"jsonrpc":"2.0","id":2,"method":"tools/list"}
S→C {"jsonrpc":"2.0","id":2,"result":{"tools":[{"name":"add",
"description":"두숫자를더한다.","inputSchema":{...},"outputSchema":{...}}]}}
# ③도구호출(call_tool("add", {"a": 10, "b": 20}))
C→S {"jsonrpc":"2.0","id":3,"method":"tools/call",
"params":{"name":"add","arguments":{"a":10,"b":20}}}
S→C {"jsonrpc":"2.0","id":3,"result":{"content":[{"type":"text","text":"30"}],
"structuredContent":{"result":30},"isError":false}}
알아두기
결과는사람이읽는content와프로그램이읽는structuredContent로함께반환된다. isError가true이면도구실행이실
패했다는뜻이다. FastMCP Client는이때ToolError를낸다.

docstring description
모델이도구를선택할때읽는다.

적는다

6.Harness
레퍼런스아키텍처의Agent 서버안에서모델의호출을통제하는코드가Harness이다. 모델은다음응답이나호출할도구를제안
만하고, 실행, 한도, 기록, 복구는모델을감싼Harness가담당한다.
표6㎿1  Model과Harness의역할분담
Model ㏙LLM㏚ Harness ㏙모델을감싸는코드㏚
다음응답이나호출할도구를제안한다 프롬프트와도구를선택해모델에넘긴다
도구를직접실행하지못한다 제안된도구를실행하고결과를돌려준다
몇번째시도인지, 비용이얼마인지모른다 반복횟수, 시간, 권한을제한한다
대화가끝나면아무것도기억하지않는다 상태를저장하고, 실패하면복구한다
같은모델이면팀마다차이가없다 모든단계를기록한다. 팀마다이부분이다르다
