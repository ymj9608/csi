# 대규모 코드 분석에서 비전의 도입 가치

2026-10-23. 원래 3조건 단일 실행과 별도 컴파일 교정 실험을 해석한다. 실제 결과는 `result.json`과 `RESULTS.md`를 기준으로 한다.

## 검증한 가설과 검증하지 못한 가설

- 검증한 범위: 연구자가 정한 Java 20개에서 코드 검색으로 9개를 선택하고, 동일한 코드에 공식 그림의 분석 맥락을 추가했을 때 한 번 생성한 패치의 품질.
- 검증하지 못한 범위: 15,499개 파일 전체에서 자율 탐색하여 필요한 파일을 찾아내는 능력, 운영 보안 전체, 장기 반복 사용의 비용 우위, 다수 프로젝트에서의 통계적 성능.
- `전체 범위`는 전체 저장소가 아닌 20개 파일이다. 20→9개의 결과를 전체 저장소 크기에 선형 외삽하면 안 된다.
- 현재 그림은 Client/JobManager/TaskManager를 보여주지만 S3/TLS 구현 파일을 구체적으로 연결하지 않는다. 비전 조건의 추가 파일은 0개였다.

## 현재 근거로 내릴 수 있는 제품 판단

전체 코드를 매번 LLM에 입력하기 어렵다는 문제의식은 타당하지만, 해결 수단이 반드시 비전이어야 하는 것은 아니다. 코드 인덱스·심볼·호출 관계·변경 파일·정적 분석 근거로 필요한 코드를 찾는 기본 경로가 먼저 필요하다. 이번 실험에서는 비전 없이도 입력 파일을 20개에서 9개로 줄였다.

따라서 현재 MVP에서 아키텍처는 선택적 보조 맥락으로 두는 것이 근거에 맞다. 그림이 없거나 오래됐더라도 코드 기반 분석을 제공하고, 그림이 보여주는 컴포넌트와 실제 저장소 모듈을 검증한 뒤 검색 우선순위에 반영한다. 그림에 없다는 이유로 변경 파일·탐지 근거·필수 설정을 제거하지 않는다.

비전의 추가 가치가 있을 수 있는 영역은 저장소에 나타나지 않는 서비스 간 개인정보 이동, 외부 SaaS, 신뢰 경계, 배포 네트워크 및 서비스와 저장소의 연결이다. 이는 이번 실험으로 입증된 효과가 아니라 다음 검증 대상이다. 원본이 draw.io/Mermaid 등 구조화된 형식이면 직접 파싱하는 대조군도 필요하다.

## 비용·지연을 비교할 때

코드 입력은 검색만 20,975토큰, 비전 추가 22,087토큰이다. 비전 맥락으로 1,112토큰이 늘었으며 최초 이미지 입력 1,115토큰과 출력 1,229토큰도 별도 발생했다. 반복 시 그림 분석을 재사용할 수 있지만 코드 요청에 추가하는 맥락은 계속 비용을 발생시킨다. 현재 데이터로 손익분기 반복 횟수를 산출할 수 없다.

캐시·순서 효과도 있다. 검색만 조건에는 제공자 입력 캐시 10,368토큰이 적중했고 다른 조건에는 없었다. 컴파일 조기 실패는 속도 개선이 아니다. 평가자가 한 API 표현식을 고친 시간은 미측정이므로 교정 조건을 자율 AI의 성공까지 시간/비용으로 표시하지 않는다.

## 다음에 필요한 공정한 실험

1. 개인정보 저장·로그·외부 전송·서비스 간 호출 등 서로 다른 작업을 여러 저장소에서 선정하고 정답 경로와 테스트를 미리 고정한다.
2. 동일한 코드 검색을 기본으로, 이미지 없음 / 이미지 추가 / 같은 구조를 텍스트로 제공의 세 조건을 비교한다. 비전 인식 효과와 구조 정보 자체의 효과를 분리한다.
3. 동일한 모델·수정 예산·테스트 피드백·최대 재시도를 제공하고 순서를 섞어 반복한다. 모델 실패, 형식 오류, 컴파일 실패도 모두 보존한다.
4. 정확한 그림뿐 아니라 오래된 그림·누락된 연결·잘못된 모듈 매핑도 포함한다. 정답을 그림에만 노출해 유리하게 만들지 않는다.
5. 필수 경로 재현율, 전체 테스트 성공률, 성공까지 총 토큰/시간/비용, 추가 조회 횟수, 사람의 개입을 측정한다. 최초 그림 분석과 재사용 시나리오는 별도로 보고한다.
6. 운영에 필요한 허용 실패율·효율 개선 기준을 실험 전에 정한다. 품질을 유지하며 비전 비용 이상으로 조회/재시도가 줄어드는지로 도입을 결정한다.
