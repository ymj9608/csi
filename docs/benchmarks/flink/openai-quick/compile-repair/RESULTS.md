# 코드 검색 컴파일 오류 교정 후 재검증

2026-10-23. 평가자가 기존 AI 패치의 API 표현식 한 곳을 교정했다. 새로운 AI 생성 호출은 없으며 원래 첫 시도 결과는 덮어쓰지 않았다. 전체 입력/비전 조건은 이전 실행 결과를 재사용했다. 따라서 자율 AI 재시도 성능 또는 조건 간 통계적 우위를 입증하는 실험이 아니다.

## 수정과 실행

`SecurityOptions.isRestSSLHostnameVerificationEnabled(config)`를 실제 Flink API인 `config.get(SecurityOptions.SSL_REST_VERIFY_HOSTNAME)`로 치환했다. 다른 코드와 평가 기준은 변경하지 않았다. [교정 diff](correction.patch), [전체 후보 diff](candidate.patch).

같은 61개 테스트를 새 소스·의존성 복사본에서 실행했다. 네트워크 차단, Docker 4GiB/2CPU, swap 금지, 순차 실행을 유지했다. 재현 명령: 저장소 루트에서 `PYTHONPATH=. .venv/bin/python scripts/recheck_flink_compile_repair.py`. 결과 폴더가 이미 존재하면 덮어쓰지 않고 종료한다.

교정 후 실패는 `securityV5NoKeystorePasswordLoggingOnFailure` 하나다. 실제 테스트 로그에 합성 키스토어 비밀번호가 출력됐다. 컴파일 오류만 해결하면 충분한 것이 아니라 민감정보 로그 제거도 필요하다. 비전 후보는 이 보안 문제를 해결했으나 안전한 진단 로그 계약을 깨뜨렸다. 두 후보의 60/61이라는 합계가 같은 위험도를 뜻하지는 않는다.

검증기는 Maven의 test-failure-ignore 옵션을 사용해 끝까지 테스트 결과를 수집한다. Maven exit code 0 또는 BUILD SUCCESS만으로 합격 처리하지 않고 개별 테스트 결과와 보호 조건으로 판정하며, 이번 `accepted`는 false다.

교정 자체의 추가 API 호출/비용은 0이다. 사람에 해당하는 평가자의 수정 시간은 미측정이다. 원래 생성 4.78초와 비용 $0.01262를 자동 수정 성공까지 비용으로 보고해서는 안 된다. 원래 실패 검증 55.09초와 재검증 131.74초를 모두 남겼으며, 재검증만으로 비전보다 빠르다고 단정하지 않는다.

## 비전 도입 관점의 판단

이번에는 비전 없이도 9개 파일에서 컴파일 가능한 패치를 만들 수 있었고 안전한 기존 동작도 보존했다. 비전 후보에서는 추가 보안 문제 하나가 해결된 관측이 있으나, 이는 단일 실행이며 교정 후 검색 조건에는 평가자 개입이 있다. 비전의 순수 효과나 자율 성공률 차이로 확정할 수 없다.

대규모 코드 입력 제한을 해결하는 데 검색이 기여했다는 점은 확인했지만, 비전의 추가 파일 탐색 이득은 관측되지 않았다. 검색만 입력 20,975토큰 대비 비전 22,087토큰으로 오히려 1,112토큰 증가했다. 최초 이미지 분석도 약 9.31초가 든다. 이미지 캐시를 재사용해도 매 코드 호출에 붙는 구조 설명 비용은 남는다.

현재 MVP에서는 코드 검색·정적 근거·테스트 검증을 기본으로, 아키텍처를 선택적 보조 정보로 유지하는 것이 타당하다. 비전의 가치는 서비스 간 흐름·외부 전송·신뢰 경계처럼 코드 검색만으로 알기 어려운 정보를 실제 파일과 연결할 때 별도로 검증해야 한다. 구체적인 다음 실험과 한계는 [도입 가치 분석](DESIGN_ASSESSMENT.md)에 정리했다.

원시 근거: [결과 JSON](result.json), [Maven 로그](validation/maven.log). 비용·시간의 원래 비교는 [최초 보고서](../RESULTS.md)를 참조한다.
