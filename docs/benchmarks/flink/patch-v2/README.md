# 비전이 실제 수정 코드에 도움이 되는지 평가하는 v2

최신 빠른 실측은 [OpenAI 비교 결과](../openai-quick/RESULTS.md), 데이터셋 수집 항목과 팀원용 설명은 [Perception & Reasoning](../../../PERCEPTION_REASONING.md)을 확인하세요. 아래는 원래 로컬 반복 실험 설계이며, 해당 실행은 시간·메모리 요구로 중단됐습니다.

목표는 **같은 기능·보안 품질을 유지하면서 전체 처리 비용을 줄이는 것**, 또는 **동일한 자원 한도에서 더 많은 수정안을 검증 통과시키는 것**입니다. 비전의 성공을 미리 전제하지 않습니다. 파일 수·입력 토큰만 줄었는데 취약점이나 기능이 빠지는 결과는 성공으로 집계하지 않습니다.

기존 [v1 결과](../RESULTS.md)는 진단 실험으로 그대로 보존합니다. v2는 모델이 실제 패치를 만들고 고정된 테스트로 평가하는 별도 실험입니다. 이 폴더의 [사전 점검](preflight.json)과 [초기 환경 기록](calibration.json)은 구현 당시의 미실행 기록입니다. 후속 실험은 별도 [실측 폴더](../patch-v2-run/)에 저장하며 이전 기록을 덮어쓰지 않습니다. Maven 3.9.16·Java 17 환경에서 참조 수정본의 61개 테스트 실행을 확인했고, 모델 실행 전 새 환경에서 양·음성 대조군을 다시 검증합니다.

## 수정 전과 수정 후

| 항목 | v1 | v2 |
| --- | --- | --- |
| 평가 대상 | 위험 설명·코드 인용 | AI가 생성한 실제 패치의 동작 |
| 선택 방식 | 그림+파일명으로 최대 4개 | 스캐너·변경·설정 근거 보존, 동일 인덱스, 추가 조회 |
| 대조군 | 코드 전체 / 그림으로 선별 | 선언 범위 전체 / 코드 검색 / 같은 코드 검색+비전 |
| 수정 코드 | 실험자가 주입 변경을 되돌림 | 세 방식 모두 동일한 로컬 Ministral이 생성 |
| 품질 판정 | 라벨 위치·인용 일치 | 빌드, 취약점 5개 테스트, 기존 기능, 안전한 로그 보존 |
| 시간 판정 | 개별 추론 시간 | 선택·조회·패치 생성·검증·실패 및 최초 비전 분석 포함 |
| 반복 | 방식별 1회 | 동일 문제 3회, 방식 순서 균형 배치, paired seed |
| 캐시 | 최초 비전 시간을 뺀 계산 | 실제 저장된 맥락을 매 요청 다시 읽음 |
| 결론 | 토큰 절감과 품질 하락 병존 | 품질 통과 조건을 만족한 경우에만 효율 개선 판정 |

## 고정 데이터와 공정한 대조

- 공개 Apache Flink 커밋 `8d01380ff5bf9892462ef9808b1b56fd9723f54d`와 v1의 합성 변경을 사용합니다. 실제 upstream 취약점이라는 주장이 아닙니다.
- 조회 범위는 `flink-runtime/.../security/token`, `flink-runtime/.../net`, S3 token 모듈의 Java 파일 및 `SecurityOptions.java`입니다. 현재 **20개·173,112 bytes**입니다. “전체 코드”는 이 선언 범위이며 Flink 전체 저장소가 아닙니다.
- 다이어그램은 v1의 공식 그림을 그대로 사용합니다. 정답을 보고 파일명이나 취약점 위치를 그림에 추가하지 않습니다.
- 동일한 4개 변경 파일, 스캐너 근거, 설정 계약 파일을 세 방식에 모두 제공합니다. 설정 파일은 스캐너가 찾은 취약점으로 위장하지 않고 `CONTRACT`로 기록합니다. TLS 설정의 기본값은 false이며 이번 수정 목표는 **명시적으로 true를 설정했을 때 이를 존중하는 것**입니다.
- 최종 패치를 만드는 모델은 모두 `ministral-3:8b-instruct-2512-q4_K_M`입니다. 동일 temperature 0, seed, 컨텍스트·출력 한도, 조회 한도, 편집 허용 경로를 사용합니다. 응답 모델명과 로컬 모델 digest를 기록합니다.
- 비전 제공자는 실행 전에 고정합니다. 기본은 OpenAI `gpt-5.4-mini-2026-03-17`, 별도 실험에서 `qwen3-vl:8b`를 사용할 수 있습니다. 제공자가 다른 실행을 한 대조군으로 섞지 않습니다.
- 정답 라벨, 참조 패치, 새 테스트 코드와 채점 결과는 모델 입력에 넣지 않습니다. 다이어그램 추출에는 후보 파일 목록도 제공하지 않습니다.
- 5개 문제를 묶은 **업무 1개 × 3회 반복 × 3방식**입니다. 독립적인 업무 15개로 부풀리지 않습니다.

## 실행 로직

```text
공통: 고정 커밋·변경 파일·스캐너 결과·설정 계약
  ├─ full_code: 선언 범위 20개 파일을 빠짐없이 배치 검토
  ├─ code_index: 필수 근거 + 코드 관계·식별자 검색
  └─ vision_index: 같은 검색 결과 + 저장된 그림 맥락·추가 관련 경로
       ↓
같은 Ministral로 코드 검토 / 필요한 경로 추가 조회(최대 2라운드)
       ↓
같은 변경 파일 원문 + 검토 근거 → 실제 search/replace 패치 1개 생성
       ↓
격리된 Flink 복사본에 적용 → 고정 테스트 실행 → 통과/실패와 비용 기록
```

비전은 코드 검색 결과를 삭제할 수 없습니다. 코드 인덱스가 선택한 파일과 비전 추가 파일의 합집합을 사용합니다. **그림 밖의 토큰 수신 파일을 누락했던 v1 문제를 예방하는 장치**입니다. 추가 파일이 생기면 시간과 토큰도 그대로 증가합니다. 이 보수적인 방식에서 기대하는 비전 이점은 관련 모듈의 의미 파악, 추가 탐색 감소, 잘못된 패치 감소이며, 인덱스보다 초기 파일이 무조건 줄어드는 구조는 아닙니다.

필수 근거가 한 번의 입력 예산을 넘으면 파일을 버리지 않고 배치로 나눕니다. 파일 하나가 48,000 bytes를 넘거나 필요한 추가 조회가 한도를 넘으면 명시적으로 실패합니다. 바이트 예산은 요청 크기 제한이며 **실측 토큰 수가 아닙니다**. 최종 패치 요청에는 모든 편집 허용 파일의 원문을 다시 제공합니다. 검토 메모로 원문을 대체하지 않습니다.

그림을 해석하지 못하면 코드 검색으로 전환하고 그 비용을 기록합니다. 이 실행에서 좋은 결과가 나와도 `VISION_FAILED_FALLBACK_ONLY`로 표시하며 비전 성과라고 주장하지 않습니다. 코드 매핑이 추가 후보를 찾지 못해도 그 사실을 남깁니다. 그림의 설명 맥락이 패치 품질에 도움이 됐는지는 실제 테스트로 판단합니다.

최초 이미지 해석은 캐시에 저장하고 매 요청 실제 파일에서 읽습니다. 캐시 키에 커밋·이미지·모델·제공자·프롬프트·스키마를 포함하고 내용 해시도 검증합니다. 소스·그림·실행기·테스트가 바뀌면 같은 고정 실험으로 실행할 수 없습니다.

## 코드 품질을 판정하는 테스트

추가한 3개 JUnit 클래스는 실제 Flink 클래스를 호출합니다. AWS 외부 연결 대신 SDK의 합성 자격증명 객체를 사용하고, TLS는 로컬 엔진 설정과 upstream 테스트 키스토어를 사용합니다.

| 검증 | 실패해야 하는 변경 전 동작 | 수정 후 필요한 동작 |
| --- | --- | --- |
| V1 | 직렬화한 위임 토큰을 Base64로 로그에 남김 | 토큰을 수신자에게 그대로 전달하면서 로그에서 제외 |
| V2 | S3 세션 토큰을 로그에 남김 | 연속 갱신 후 자격증명은 최신 값, 비밀은 로그에 없음 |
| V3 | DEBUG 로그에 secret key를 남김 | 공급자 초기화와 자격증명 사용 여부 유지, 비밀 출력 없음 |
| V4 | true로 설정해도 REST hostname 검증을 끔 | true이면 HTTPS 검증, false의 기존 계약도 유지 |
| V5 | 키스토어 초기화 실패 경로에서 password 출력 | 실패해도 원문 비밀번호 로그 없음 |
| 정상 대조 | 바이트 수·완료 이벤트·`[REDACTED]` 로그 | 안전한 로그를 실제로 계속 출력 |

Flink의 기존 `SSLUtilsTest`, 토큰 수신자 테스트, S3 공급자·수신자 테스트도 같은 명령으로 실행합니다. 추가 테스트 11개 중 보안 5개, 기능·안전 로그 6개입니다. 기존 테스트가 몇 개 실행되는지는 실제 Surefire 결과에서 결정하며 미리 통과 수치를 만들지 않습니다. TLS V4 추가 테스트는 엔진 설정을 검증하며 실제 공격 환경이나 배포 보안 전체를 보증하지 않습니다.

모델 실험 전에 `calibrate`가 **주입본에서 정확히 보안 5개 실패, 참조 수정본에서 전부 통과**하는지 검사합니다. 참조 수정본은 테스트가 올바른지 확인하는 용도이며 모델 성과에 포함하지 않습니다. 컴파일 실패, 실행 누락, 예상 외 실패가 있으면 실험을 차단합니다.

후보 패치의 통과 조건은 모두 충족해야 합니다.

1. 허용된 원문 위치에만 적용되고, 빌드·테스트 명령이 정상 종료됩니다.
2. 보안 5개가 모두 통과합니다.
3. 참조본에서 통과했던 기존·추가 기능 테스트를 하나도 빠뜨리거나 새로 skip하지 않습니다.
4. 안전한 로그를 유지하고 테스트 파일은 변경되지 않습니다.

테스트·설정·빌드 파일 편집은 허용하지 않습니다. 후보 Java는 네트워크 없는 Docker 컨테이너에서만 실행하고 호스트의 `.env`·저장소 자격증명은 마운트하지 않습니다. 모든 실행은 새 소스/의존성 캐시 복사본을 사용합니다. 모델 출력에는 테스트 결과를 되돌려주지 않으며, **pass@1**로 평가합니다. 여러 번 고쳐 통과시키는 실험은 별도 프로토콜로 추가해야 합니다.

## 성과 판정과 로그

`measurements.jsonl`에는 실패를 포함한 모든 예약된 실행의 선택·추가 조회·생성·검증 시간, 입력/출력 토큰, 검증 결과, diff 크기와 사용 모델을 남깁니다. `calls/`는 실제 요청과 응답, 제공자 usage, 로컬 모델 로드/prefill/생성 시간을 남깁니다. 키와 비공개 reasoning은 저장하지 않습니다. 제공자 토큰이 없으면 `null`이며 0으로 계산하지 않습니다. 최초 비전 입력/출력 토큰은 별도 및 합산 항목으로 공개합니다. 서로 다른 모델의 토큰 합계는 처리량 지표이며 원화 비용과 동일하지 않습니다.

| 성과 | 판단 방법 |
| --- | --- |
| 수정 코드 품질 개선 | 같은 seed·업무에서 새 기능 회귀 없이 전체 검증 통과한 패치가 증가 |
| 관측된 품질 유지 | 기준군이 통과한 모든 반복에서 비전군도 통과; 양쪽 모두 실패한 경우는 제외 |
| 시간 개선 | 위 품질 조건 충족 + **초기 분석을 포함한 실제 전체 실행 합계** 감소 |
| 반복 요청 시간 | 저장된 캐시를 읽고 검증을 끝낼 때까지 실제 요청 시간 합계 |
| 토큰 절감만 발생 | 시간 개선과 분리해서 보고; 초기 비전 토큰도 별도 합산 |
| 결과 미완료·비전 실패 | `INCOMPLETE` / `VISION_FAILED_FALLBACK_ONLY`; 성공 결론 금지 |

`vision_index ↔ full_code`는 전체 입력 대비 제품 효과, `vision_index ↔ code_index`는 **이미 검색을 최적화한 상태에서 비전의 추가 가치**를 봅니다. 두 번째 비교에서도 개선돼야 비전 자체를 도입할 근거가 강해집니다. 이미지에서 얻은 구조 정보와 그 정보를 텍스트로 받았을 때의 효과를 분리하려면 동일 구조 텍스트 대조군을 후속으로 추가해야 합니다.

이번 반복은 표본이 작아 통계적 비열등성을 입증하지 않습니다. v1 결과를 이미 본 개발용 데이터이므로 긍정적인 결과가 나와도 별도 저장소·업무의 미사용 평가 세트로 확인해야 합니다. 후속 세트에는 그림에 없는 저장 경로, 비동기 소비자, 잘못된/오래된 그림, 큰 변경 범위, 이름이 모호한 모듈과 정상 대조군을 함께 포함합니다. 성공한 사례만 골라 보고하지 않습니다.

## 실행 방법

CSI 루트에서 실행합니다. [실행기](../../../../scripts/benchmark_flink_patches.py), [선택·패치·집계 로직](../../../../scripts/flink_patch_protocol.py), [격리 검증기](../../../../scripts/flink_patch_validation.py)를 사용합니다.

```bash
# 새 데이터/모델/구현이면 별도 output 경로로 고정합니다.
.venv/bin/python scripts/benchmark_flink_patches.py prepare

# 사전 준비: Docker의 Maven+Java 17 이미지와 Linux Maven 의존성 캐시.
# 이 명령 자체는 모델 호출을 하지 않습니다.
docker pull maven:3.9.16-eclipse-temurin-17
.venv/bin/python scripts/benchmark_flink_patches.py calibrate

# calibration.json이 READY인 경우에만 실제 모델 실험이 가능합니다.
# OpenAI: 공개 그림 1회. 코딩 모델: 최악 9회 실험 × 최대 10회 = 90회 로컬 호출.
.venv/bin/python scripts/benchmark_flink_patches.py run --allow-openai-public-data

# 모델 재호출 없이 집계
.venv/bin/python scripts/benchmark_flink_patches.py summarize
```

컨테이너는 자동으로 이미지를 받거나 의존성을 다운로드하지 않습니다. 이미지가 있어도 CSI 내부 `.runtime/flink-patch-v2/m2`에 **고정 커밋의 Linux 빌드에 필요한 의존성**이 준비되지 않았으면 Maven offline 빌드가 실패할 수 있습니다. 개인 `~/.m2`는 사용하지 않습니다. 신뢰한 원본 소스의 별도 복사본에서 같은 두 모듈과 의존 모듈을 Java 17/Maven 3.9.16으로 먼저 빌드해 캐시를 준비해야 합니다. 고정 커밋의 enforcer가 Maven 3.9.16을 요구하므로 버전을 낮추거나 검사를 우회하지 않습니다. 공통 Maven 설정은 `tests/fixtures/flink_patch_eval/maven-settings.xml`이며 Maven Central의 Google 미러를 사용합니다. 실제 모델 후보를 실행하는 단계에서는 네트워크를 계속 차단합니다. 기존 CSI/Lichu 서비스의 컨테이너나 설정은 변경하지 않습니다.

각 후보는 매번 새 소스·의존성 캐시에서 컴파일합니다. Maven에는 `maven.test.failure.ignore=true`를 주어 앞 모듈에서 실패해도 뒤 모듈의 테스트를 실행합니다. **통과 판정은 Maven 종료 코드만으로 하지 않으며**, Surefire XML의 전체 필수 테스트 통과·보안 5개·안전 로그·테스트 원본 보존을 모두 확인합니다.
