# 첫 실행: Ollama 스키마 오류 기록

로컬 요청 9건이 모두 HTTP 400으로 실패해 **수정 코드 품질은 측정하지 못했습니다**. 그림 분석은 성공했습니다. 오류 원인과 보정 내용은 [후속 실행 변경 기록](../patch-v2-final/amendment.json), 실제 패치 비교는 [후속 결과](../patch-v2-final/EVALUATION.md)를 확인하세요. 아래는 첫 실행에 적용하려던 절차입니다.

# Flink 패치 실측 자료

[최종 결과표](EVALUATION.md)는 모델이 직접 생성한 수정 코드를 평가합니다. 이전 [진단 실험](../RESULTS.md)의 연구자 복원 패치를 모델 성과로 집계하지 않습니다. [실험 설계](../patch-v2/README.md)를 함께 확인하세요.

## 데이터와 비교 방법

- 공개 Flink 커밋 `8d01380ff5bf9892462ef9808b1b56fd9723f54d`의 Java 20개 파일, 173,112 bytes를 선언 범위로 고정했습니다. 저장소 전체를 LLM에 전달한 실험은 아닙니다.
- 4개 파일에 토큰·비밀번호 로그 노출과 TLS 설정 회귀 등 합성 결함 5개를 주입했습니다. 공개 원본의 실제 취약점이라는 의미가 아닙니다.
- 모든 방식에 같은 변경 파일·스캐너 근거·설정 계약·업무 지시를 줍니다. 모든 수정은 같은 로컬 Ministral 3 8B가 생성합니다.
- `full_code`: 선언한 20개 파일을 모두 나누어 검토합니다.
- `code_index`: 필수 근거와 코드 관계 검색으로 선택한 파일을 검토합니다.
- `vision_index`: 같은 코드 검색에 공식 구조 이미지에서 실제 추출한 맥락을 추가합니다. 비전이 코드 검색의 필수 파일을 제거할 수 없습니다.
- 최초 그림 해석 1회는 OpenAI `gpt-5.4-mini-2026-03-17`을 사용합니다. 공개 그림만 외부로 보내며 비공개 정책·프로젝트·환경 변수 값은 보내지 않습니다.
- 방식별 3회, 총 9회 실행합니다. 반복별 호출 순서를 바꾸고 같은 반복의 seed를 맞춥니다. 추가 조회는 최대 2라운드, 로컬 호출은 실행당 최대 10회입니다.
- 실제 패치의 첫 시도만 평가합니다. 테스트·참조 수정본·정답 라벨은 모델에게 제공하지 않으며 실패 후 정답으로 수정하지 않습니다.

## 품질과 시간

보안 5개, 기능·안전 로그 56개, 총 61개 JUnit 테스트를 동일하게 실행합니다. 모든 필수 테스트가 통과하고 테스트 원본이 보존되어야 수정안을 통과시킵니다. 테스트 적용·컴파일·실행이 실패한 후보도 전체 분모에 남깁니다.

매 후보는 네트워크 없는 Docker에서 새 소스·새 의존성 캐시 복사본으로 빌드합니다. Java 17/Maven 3.9.16 이미지의 실제 ID를 고정합니다. 빌드 의존 관계에 따른 reactor는 41개 모듈이며, 이는 모델에 입력한 20개 파일과 구분해야 합니다.

전체 지연에는 파일 선택, 추가 조회, 코드 생성, 격리 빌드·테스트와 작업 공간 정리가 포함됩니다. 최초 비전 해석은 따로 측정하여 3회 누적 시간에 한 번 더합니다. 이미지·Maven 의존성 다운로드, 공통 환경 준비, 검증기 교정은 사전 준비 단계로 분리합니다.

## 파일 확인 순서

1. `protocol.json`: 호출 전 고정한 범위·모델·예산·실행 순서·소스와 구현 해시.
2. `calibration.json`: 주입본에서 보안 5개 실패, 참조본에서 전부 통과했는지 검증.
3. `calls/`: 실제 요청과 응답·토큰 usage·로컬 로드/입력 처리/생성 시간. 이미지 자체는 상위 폴더 `architecture.png`이며 요청 로그에는 해시를 남깁니다.
4. `architecture-cache.json`: 실제 비전 추출 결과와 캐시 식별자.
5. `trials/`: 선택 파일, 추가 조회 메모, 모델 생성 diff, Maven 로그, 검증 결과.
6. `measurements.jsonl`: 실패를 포함한 전체 실행 기록.
7. `EVALUATION.md`, `evaluation.json`: 사람이 읽는 결과표와 상세 집계.

## 재집계

CSI 루트에서 아래 명령은 모델을 다시 호출하지 않습니다.

```bash
.venv/bin/python scripts/summarize_flink_patch_run.py \
  --output docs/benchmarks/flink/patch-v2-run
```

새 모델 실험은 기존 `calls/`를 삭제해 재실행하지 말고 별도 output 폴더로 프로토콜을 고정해야 합니다. 준비·교정·실행 명령은 [설계 문서](../patch-v2/README.md)에 있습니다. 이번 실험은 독립된 평가 실행기이며 운영 CSI의 Lichu 코딩 프로필과 구분됩니다.
