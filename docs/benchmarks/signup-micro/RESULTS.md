# 2단계: 구조 인식을 가정한 회원가입 전화번호 추가

2026-10-23. 사용자 결정에 따라 1단계 그림 인식은 팀원이 담당하며 이 실험에서 실행하지 않았다. 준비 시 작성된 protocol.json의 stage1 재사용 문구는 실행 계획 초안이며, 실제 비교에는 이전 Qwen 점수를 사용하지 않는다.

## 범위와 가정

이미지를 완벽하게 읽었다는 가정의 구조 텍스트를 평가자가 제공했다. 회원 서비스→DB, 회원 서비스→외부 관측 이벤트 경로를 Python/SQLite 2파일로 단순화했다. Flink 그림의 회원가입 구현 또는 Lichu 실제 코드가 아니다. 기존 전체 아키텍처와 기능 수준의 동일성을 주장하지 않는다.

공통 요구사항은 ASCII 010+8자리 전화번호 추가, 미입력 허용, 잘못된 값의 DB/이벤트 기록 전 거절, 기존 사용자·멱등 마이그레이션 보존, 소유자만 조회, 개인정보 이벤트 노출 방지, SQL 매개변수화와 허용 필드 처리다. 두 조건에 동일한 전체 소스와 요구사항을 제공했다. 정답 패치와 테스트 코드는 모델에 전달하지 않았다.

- 코드만: 공통 요구사항+같은 두 파일로 1회 생성.
- 구조 지시문: 가정된 정확한 구조+공통 요구사항으로 지시문 1회 생성, 이를 같은 두 파일과 함께 코딩 모델에 전달하여 1회 생성.
- 지시문 및 코딩 모델 모두 `gpt-5.4-mini-2026-03-17`. 빠른 파일럿이며 실제 Qwen→Ministral 조합이나 이미지 처리 성능은 검증하지 않았다.
- 총 모델 호출 3회, 재생성 0회, 로컬 모델 로드 0회. 실행은 네트워크 차단·읽기 전용·256MiB/1CPU Docker로 조건별 순차 처리했다.

## 테스트와 결과

기능 4개: 전화번호 실제 저장/조회, 기존 회원가입, 기존 스키마 이관·반복 초기화, 가입 이벤트 유지.
보안 계약 9개: SQL 형태 입력, 개행 로그 주입, HTML 문자열, 전각 숫자, 과대 입력, 잘못된 타입, 외부 이벤트 원문 노출, 타인 조회, id/role 과다 필드 주입.

SQL/HTML 사례는 입력 거절을 확인하는 테스트이며 실제 HTTP 공격·브라우저 XSS·모든 SQL 경로의 안전을 증명하지 않는다. 기존 코드는 전화번호를 무시했으므로 기준 5/13을 기존 서비스의 보안 점수로 해석하지 않는다. 전화번호를 넣은 새로운 요구사항의 미구현을 포함한다.

### 12/13의 의미와 후속 검사

구조 지시문 후보는 알 수 없는 `id`, `role` 필드가 있으면 ValueError로 요청 자체를 거절했다. 원래 테스트는 그 필드를 무시하고 가입 성공하는 것만 허용해 ERROR를 냈다. 이는 공격 성공이나 권한 상승이 아니다. 원래 코드가 불필요 필드를 무시했던 것과 비교하면 API 동작 차이는 있다.

후속 테스트에서는 양쪽 모두 동일하게 안전한 거절도 허용하고, 거절 시 DB 행 및 이벤트가 생성되지 않는지 검사했다. 양쪽 13/13이다. 이는 결과를 본 뒤 평가 기준을 확장한 보조 분석이며 사전 결과를 대체하지 않는다. 원래 테스트·결과 및 후속 테스트·결과를 별도 폴더에 보존했다.

## 해석

이 작은 작업에서는 구조 정보 없이도 요구사항과 소스만으로 구현·검증이 가능했고, 구조 지시문의 추가 품질/효율 이득은 관측되지 않았다. 오히려 모델 시간이 4.13→9.04초, 총 입력이 440→868토큰으로 늘었다. 한 작업·한 번씩의 결과로 비전이 일반적으로 무가치하다고 결론낼 수는 없다.

정확한 구조가 있다고 가정해도 쉬운 과제에서는 이점이 없을 수 있다. 이 실험은 검색 파일 감소를 평가하지 않았다. 구조의 추가 가치는 여러 서비스·저장소의 개인정보 이동이나 코드만으로 드러나지 않는 배포 경계를 알아야 하는 과제에서 별도로 검증해야 한다. 이 테스트만을 근거로 전체 시스템 공격 방어, 암호화, 휴대전화 소유권 확인, 개인정보 법령 준수를 주장하지 않는다.

## 재현 및 근거

- `scripts/benchmark_signup_micro.py`: 준비·실제 호출·최초 테스트, 기존 결과 덮어쓰기 방지.
- `scripts/recheck_signup_security.py`: 새 모델 호출 없이 안전한 거절 후속 테스트.
- `protocol.json`: 정확한 공통 과제·시스템 지시·구조 가정·소스/테스트 해시.
- `calls/*-input.json`: 실제 모델별 프롬프트, `calls/*.json`: 응답·usage·시간.
- `code_only`, `oracle_handoff`: 생성 소스·diff·13개 테스트 및 로그.
- `*-security-check`: 사후 보조 평가 소스·테스트·로그.
- `comparison.json`: 최초 실행 비교 원시 집계. 보조 평가로 덮어쓰지 않음.

원래 서비스 코드는 수정하지 않았다. 지시문은 JSON의 handoff 문자열로 운반되지만 코드 모델에 전달되는 내용은 자연어 작업 지시문이며 추출 그래프를 다시 생성하는 단계는 없다.
