개인정보 유출 MVP 비교 실험 결과
================================

결론
이미지 추가 3/4 시나리오 성공, 코드-only 2/4 성공이다.
요청한 이미지 4/4 · 코드-only 3/4 조건은 나오지 않았다.
일관된 Vision 우위나 안정적인 자동 수정 성능을 입증하지 못했다.
CSI 운영 엔진·승인·검증 기준은 변경하지 않았다.
작업 브랜치: experiment/privacy-mvp-vision (현재 작업 트리, 커밋·푸시 없음).

데이터와 실행 방식
- 직접 작성한 작은 Python 서비스 4종: 일반 전송, 장애 우회, 외부 감사 로그, 중첩 회원 데이터.
- 시나리오당 Python 2개(app.py, adapter.py)와 deployment.json을 두 조건 모두에 전체 제공.
- 수정은 adapter.py 한 파일로 제한. 모델이 생성한 코드는 WASI 읽기 전용·네트워크 없는 환경에서 실행.
- VLM: qwen3-vl:8b-instruct-q4_K_M / Coding Agent: ministral-3:8b-instruct-2512-q4_K_M.
- 같은 VLM이 코드-only에서는 텍스트만, 이미지 조건에서는 텍스트와 PNG를 읽는다.
- 서버가 VLM 지시 → 코드 생성 → 고정 검증을 실행하고, 실패 시 오류·이전 수정안을 주어 한 번 재지시한다.
- 최대 2개 수정안, 호출당 300초, 컨텍스트 8192, temperature 0, seed 42, CPU thread 3.
- 4개 검증 계약: 정상 외부 전송, 장애 외부 전송, 내부·저장 데이터 보존, 직접 호출·원본·전송 동작 보존.
- 각 테스트 안에 여러 입력과 단언이 있다. 단순히 테스트 개수를 줄여 보안 조건을 생략한 것은 아니다.
- 예비 직접 코딩 과제는 첫 시도 4/4, 43.009초. 아래 비교 성적과 시간에서는 제외한다.

정량 요약
- 코드-only: 2/4(50%), 첫 수정안 성공 1/4, 평균 전체 시간 310.929초.
- 코드+이미지: 3/4(75%), 첫 수정안 성공 1/4, 평균 전체 시간 412.529초.
- 전체 5/8 성공, 비교 조건 누적 시간 2893.831초(48.23분).
- 비교 조건 모델 호출 28회, 호출 오류·시간 초과 0회, 입력 40,774토큰 / 출력 5,378토큰.
- 시간에는 모델 로딩, 지시, 코드 생성, 재시도, 검증, 정리가 포함된다.
  도구 설치, 데이터·이미지 작성, 사전 테스트, 중단된 v1, 예비 코딩 과제는 제외한다.
- 두 조건 모두 성공한 동일 시나리오는 중첩 회원 정보 하나이다.
  이미지 조건은 이 과제에서 480.699초, 코드-only는 393.728초로 더 오래 걸렸다.
- 입력·출력 길이와 재시도 횟수가 다르므로 평균 시간만으로 효율 우위를 주장하지 않는다.

정성 관찰
1. 일반 전송: 이미지 조건은 재수정 후 내부 데이터를 유지하면서 외부 필드를 삭제했다.
   코드-only의 두 번째 후보는 원문을 [REDACTED]로 대체해 이번 '필드 삭제' 계약에는 실패했다.
   원문 유출이 계속됐다는 뜻이 아니다. 이 실패를 개인정보 차단 능력의 실패로 단정하면 안 된다.
2. 장애 우회: 코드-only 후보는 사용하지 않는 r2까지 모든 설정 채널로 전송했다.
   이미지 지시문은 실제 실패 대상 r3를 명시했고 첫 후보가 통과했다.
3. 감사 로그: 코드-only가 먼저 통과했다. 이미지 후보는 내부 로그의 event 묶음을 풀어 구조를 훼손했다.
   두 번째 이미지 후보는 외부 개인정보 제거는 개선했지만 내부 로그 구조를 복구하지 못했다.
4. 중첩 데이터: 코드-only는 처음에 최상위 필드만 처리했고, 이미지는 처음에 내부 데이터까지 정제했다.
   두 조건 모두 재지시 후 통과했다.
5. 정형화된 첫 구조 응답의 외부 활성 수신처·정상·장애 목록이 모두 맞은 경우는 코드-only 1/4,
   이미지 3/4였다. 단일 소형 그림의 보조 진단이며 일반적인 시각 인식 정확도가 아니다.
   원본 ID와 그림 전체 라벨을 구분한 사후 정규화 점수도 diagnostics.json에 별도 보존했다.

해석 제한과 반영 결정
- 4개 합성 과제, 조건별 1회이다. 실제 프로젝트, 새로운 취약점 발견, 통계적 우위를 입증하지 않는다.
- 이미지의 경로·신뢰 경계 사실은 코드/설정에도 있지만, 시나리오 제목은 텍스트 입력에 따로 제공하지 않았다.
  따라서 이미지 표현 자체의 효과만 분리한 완전한 대조 실험은 아니다.
- 삭제와 안전한 마스킹을 구분하는 출력 계약은 유출 차단보다 엄격하다. 이를 성공률 해석에 명시한다.
- 네 과제 모두 같은 앱 골격을 공유한다. 네 개의 독립 실무 저장소로 해석하지 않는다.
- 프론트엔드·백엔드·PostgreSQL을 유지한 Windows 데스크톱에서 측정했다.
- 프로토콜은 seed 42에서 이미지 4/4·코드-only 3/4이면 전체 8조건을 seed 43으로 반복하도록 정했다.
  해당 조건이 충족되지 않아 seed 43은 실행하지 않았다. summary.json의 seed 43 숫자 0은 실행 건수 없는 카운터이며 0/4 실패 결과가 아니다.
- 운영 반영 조건이 충족되지 않았으므로 프로덕션 검증을 4개로 낮추거나 실패 후보를 READY로 제공하지 않았다.

재현성·무결성
- 실행기 회귀 테스트 7개 통과(Windows UTF-8 로그 읽기 회귀 포함).
- 정답 4개와 오답 대조군 16개, 총 20개가 예상대로 통과/실패했다.
- v1은 첫 시나리오 결과 집계에서 cp949 디코딩 오류로 중단됐다. v1 원본과 deviation.json 보존.
- v2는 UTF-8 로그 읽기와 중간 결과 보존만 수정했다. 모든 코드·테스트·이미지 입력 해시는 v1과 동일하다.
- 검증된 결정적 대조군만 출처를 기록해 재사용했다. 예비 과제와 모든 비교 모델 호출은 새로 실행했다.
- 14개 생성 후보의 테스트 파일과 읽기 전용 앱·설정이 원본과 동일하고 모두 실제 검증됐다.
- 이미지가 Coding Agent나 코드-only 조건에 들어가지 않았고, 최초 프롬프트에 정답·테스트 코드를 넣지 않았다.
- 모델 결과나 생성 코드를 사람이 수정하지 않았다. 원본 개인정보 대신 합성값만 사용했다.

후속 개선 순서
1. 일반 전송, 장애 전송, 내부 저장 로직을 보호하고 개인정보 투영 함수만 수정하게 하는 범위 제한을 검토한다.
2. 필드 삭제·안전한 마스킹의 허용 계약을 사전에 정하고, 두 조건에 제목·설명까지 같은 정보를 제공한다.
3. Coding Agent 단독 평가를 대표 시나리오 여러 개로 확장한다. 단순 예비 과제 한 개 통과로 준비 완료를 판단하지 않는다.
4. 별도 평가 데이터와 여러 시드로 비교하고, 같은 품질을 달성한 경우의 시간·토큰을 비교한다.
5. 실패 유형이 충분히 축적된 후 모델 교체와 파인튜닝을 비교한다. 파인튜닝 효과는 아직 검증하지 않았다.
