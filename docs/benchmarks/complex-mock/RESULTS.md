# 복잡한 합성 아키텍처 비교 실험

실제 공개 프로젝트 대신 생성한 예시 코드와 아키텍처 이미지로 네 가지 입력 방식을 비교했습니다. 아래 수치는 로컬 모델을 실제 호출한 로그의 집계이며, 정답 라벨은 모델 입력에서 제외했습니다.

데이터는 **24개 서비스 · 320개 소스/설정 파일 · 150,114 bytes · 4,208줄**입니다. 서비스별 템플릿과 합성 업무 로직을 사용했으므로 같은 크기의 실제 운영 코드가 가진 복잡도나 성능을 대표하지 않습니다.

**비전 구조를 코드와 연결했지만 추가 파일 선택 효과가 없어(`NO_SELECTION_GAIN`) 코드 인덱스의 선택으로 대체했습니다. 구조 맥락도 모델 리뷰 입력에서 제외했습니다. 후속 조회나 실행 시간이 달라도 초기 파일 선택에서 비전의 추가 이득이 생긴 것은 아닙니다. 최초 이미지 인식 비용은 더해집니다.**

## 실측 비교

| 방식 | 최초 → 추가 조회 후 파일 | 모델 호출 | 입력 토큰 | 출력 토큰 | 계획·리뷰 시간 | 실행 |
|---|---:|---:|---:|---:|---:|---|
| 전체 코드 | 320 → 320 | 10 | 63,775 | 4,984 | 465.32초 | 완료 |
| 코드·설정 인덱스 | 96 → 97 | 5 | 20,185 | 2,411 | 180.75초 | 완료 |
| 저장된 비전 구조 + 같은 인덱스 | 96 → 96 | 4 | 19,133 | 1,697 | 93.27초 | 완료 |
| 구조 JSON + 같은 인덱스 | 96 → 96 | 5 | 28,987 | 1,847 | 138.50초 | 완료 |

전체 코드는 manifest에 포함된 모든 소스를 배치로 전달합니다. 나머지 세 방식은 같은 코드·설정 인덱스, 파일/바이트 예산, 후속 조회 한도를 사용합니다. 비전 방식은 조회 계획에서 이미지 추출 구조를 재사용하며, 선택 이득이 없으면 코드 인덱스로 대체하고 구조 맥락을 리뷰 입력에 넣지 않습니다. 구조 JSON 방식은 같은 그림을 생성한 원본 구조를 직접 제공합니다. 구조 JSON에는 취약점 정답이나 파일 경로가 없습니다.

전체 코드의 최초 입력은 **8개 독립 배치**입니다. 이전 배치의 판단을 다음 배치에 전달하지 않으므로 서비스 간 데이터 출처와 사용 지점이 다른 배치로 나뉘면 근거를 함께 확인하지 못할 수 있습니다. 이는 모든 소스를 한 번에 이해하는 전체 프로그램 분석과 다릅니다.

입력 토큰은 Ollama가 각 호출에 보고한 값을 더했습니다. 출력 한도에 도달하거나 요청이 실패한 실행도 숨기지 않습니다. 계획·리뷰 시간에는 해당 방식의 파일 선택과 모델 호출이 포함되지만 최초 이미지 인식은 아래에 분리했습니다.

**불완전/실패 실행의 토큰·시간은 그 시도에서 소모한 비용입니다. 성공한 작업을 끝내는 데 걸린 시간이나 성공 처리량으로 해석하면 안 됩니다.**

## 최초 이미지 인식과 재사용 비용

이미지 1회 인식: 입력 **1,320토큰**, 출력 **2,181토큰**, **115.67초**. JSON 형식 검증: **성공**. 구조 내용의 정확도를 보장하는 판정은 아닙니다.

첫 사용의 비용 합계는 이미지 인식 + 비전 방식 계획·리뷰를 더해 입력 **20,453토큰**, 출력 **3,878토큰**, **208.94초**입니다. 이는 별도의 통합 API 요청을 잰 값이 아니라 두 실측 단계의 합입니다.

표의 비전 방식은 저장된 `vision-context.json`을 로컬 파일에서 다시 읽어 재사용한 실제 코드 리뷰 실행입니다. 이 파일 읽기는 계획 시간에 포함됩니다. DB/API 캐시 조회 지연, 최초 추출 맥락 검증·캐시 저장, 사람이 이미지를 작성한 시간, 공통 소스 수집, 예열 비용은 이 표에 포함되지 않습니다. 초기 인식 실패 후 코드 인덱스로 대체된 경우에는 비전의 효과로 해석하지 않습니다.

## 정답과 근거 품질

| 방식 | 알려진 위험 후보 | 원문 근거까지 일치 | 필수 맥락 파일 | 정상 함수 오탐 | 추가 후보 | 잘못된 본문 인용 | 잘못된 보조 인용 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 전체 코드 | 3 / 4 | 1 / 4 | 12 / 12 | 1 / 3 | 27 | 8 | 14 |
| 코드·설정 인덱스 | 1 / 4 | 0 / 4 | 10 / 12 | 1 / 3 | 12 | 3 | 6 |
| 저장된 비전 구조 + 같은 인덱스 | 1 / 4 | 0 / 4 | 10 / 12 | 0 / 3 | 9 | 4 | 3 |
| 구조 JSON + 같은 인덱스 | 2 / 4 | 1 / 4 | 9 / 12 | 0 / 3 | 8 | 6 | 8 |

후보 일치는 정답 파일·유형·행 범위가 맞는 경우입니다. 원문 검증은 해당 호출에 실제로 제공된 원문 행의 인용과 필요한 보조 근거까지 맞아야 통과합니다. 정상 대조 사례는 파일 전체가 아니라 함수의 행 범위로 판정합니다. 취약 함수와 정상 함수가 같은 파일에 있어도 서로 혼동하지 않습니다.

필수 맥락 파일의 포함 여부는 검색 범위 지표입니다. 모든 줄을 모델이 올바르게 이해했다는 뜻은 아닙니다. 로그에는 모르는 경로, 후속 조회 거절, 출력 중단도 남겨 두었습니다. 전체 보안 탐지율이나 개인정보보호법 준수율로 일반화할 수 없습니다.

집계 JSON의 `authoredLabelChecksPass`는 실행 완료·작성된 정답·인용·필수 맥락·정상 대조 사례를 확인합니다. `allMeasuredChecksPass`는 여기에 원문 응답 감사가 완료되고, 미해결·거절·후속 응답에서 버려진 추가 조회와 잘못된 보조 인용이 없어야 통과합니다. 잘못된 경로를 안전하게 거절했더라도 조회 요구를 충족한 것으로 세지 않습니다.

- **전체 코드**: 근거까지 확인하지 못한 위험 `PHONE-HTTP-1, PHONE-HTTP-2, PHONE-LOG-2`; 누락 맥락 `없음`.
- **코드·설정 인덱스**: 근거까지 확인하지 못한 위험 `PHONE-HTTP-1, PHONE-HTTP-2, PHONE-LOG-1, PHONE-LOG-2`; 누락 맥락 `services/sms_gateway/consumer.py, services/sms_gateway/provider.py`.
- **저장된 비전 구조 + 같은 인덱스**: 근거까지 확인하지 못한 위험 `PHONE-HTTP-1, PHONE-HTTP-2, PHONE-LOG-1, PHONE-LOG-2`; 누락 맥락 `services/sms_gateway/consumer.py, services/sms_gateway/provider.py`.
- **구조 JSON + 같은 인덱스**: 근거까지 확인하지 못한 위험 `PHONE-HTTP-1, PHONE-HTTP-2, PHONE-LOG-2`; 누락 맥락 `services/notification_dispatch/consumer.py, services/sms_gateway/consumer.py, services/sms_gateway/provider.py`.

## 이미지와 코드 연결

추출된 컴포넌트: **28개**, 연결: **18개**. 이 개수 자체를 구조 인식 정확도로 해석하지 않습니다.

원본 합성 그래프와 비교하면 컴포넌트 ID 일치 **28 / 28**, 방향을 포함한 연결 일치 **7 / 26**입니다. 매핑된 추가 연결 **11개**, 누락 연결 **19개**입니다.

컴포넌트 ID 또는 화면에 보이는 식별자 토큰을 정확히 대조한 결과입니다. 역할 해석·데이터 내용·보호 수단의 의미까지 맞았다는 정확도는 아닙니다. 예를 들어 브로커를 거치는 두 연결을 서비스 사이의 직접 연결로 요약하면 정확한 방향·끝점 대조에서는 불일치입니다. 이런 추상화와 의미상 잘못된 연결을 같은 오류라고 단정할 수 없습니다. 매핑되지 않은 끝점을 가진 연결은 위 추가 연결 개수에 포함되지 않으므로 전체 오탐 개수로 해석하지 않습니다.

- **저장된 비전 구조 + 같은 인덱스**: 코드 모듈 연결 22 / 28, 모호함 0, 연결 불가 6. 선택 판단 `NO_SELECTION_GAIN`, 구조 맥락 전달 `False`.
- **구조 JSON + 같은 인덱스**: 코드 모듈 연결 24 / 28, 모호함 0, 연결 불가 4. 선택 판단 `CACHED_ARCHITECTURE_NEIGHBORS`, 구조 맥락 전달 `True`.

DB·메시지 브로커·외부 서비스는 대응하는 코드 모듈이 없을 수 있으므로 연결 불가를 모두 인식 오류로 세지 않습니다. 그림에 없는 `jobs/legacy_export.py`도 코드에는 남겨 두어 누락 위험을 확인했습니다.

## 같은 입력인지 확인

모든 호출을 합친 요청 SHA256 시퀀스가 같은 쌍은 없습니다. 후속 조회가 달라졌기 때문일 수 있으므로 이 사실만으로 초기 입력 방식에 차별적인 효과가 있었다고 해석하지 않습니다.
- **코드·설정 인덱스 ↔ 저장된 비전 구조 + 같은 인덱스**: 최초 모델 요청 SHA256는 순서까지 같지만 후속 요청을 포함한 전체 시퀀스는 다릅니다. 이후 생성 응답·추가 조회 과정에서 생긴 차이를 초기 비전 파일 선택의 효과로 해석하지 않습니다.

실행 순서는 전체 코드 → 코드 인덱스 → 비전+인덱스 → 구조 JSON+인덱스로 고정했고, 모델 예열 후 캐시를 강제 초기화하지 않았습니다. 각 방식 1회이므로 캐시·순서·시스템 부하 영향을 분리한 평균 latency나 SLA가 아닙니다.

같은 최초 요청에서도 생성 응답과 그에 따른 후속 조회가 달라질 수 있습니다. 고정 seed를 사용했다는 사실만으로 생성·시간 변동을 제거한 비교라고 주장하지 않습니다. 특히 같은 코드 선택으로 대체된 방식의 단일 실행 시간 차이는 비전의 추가 성능을 입증하지 않습니다.
