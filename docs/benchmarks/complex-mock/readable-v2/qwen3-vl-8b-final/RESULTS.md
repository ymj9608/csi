# Qwen3-VL 8B: 아키텍처 그림 개선 비교

비전 **`qwen3-vl:8b`**, 코드 검토 **`ministral-3:8b-instruct-2512-q4_K_M`**로 실측했습니다. 코드 320개 파일과 원본 구조의 구성요소 28개·연결 26개를 유지하고 그림 표현을 변경했습니다. 두 이미지는 3000×2320입니다.

## 그림에서 변경한 점

- 구성요소 목록과 연결 관계를 분리했습니다. 각 연결은 독립된 행에 배치해 선 교차를 제거했습니다.
- 화살표 양쪽에 서비스 ID를 반복하고, 기존 그래프의 구성요소 종류를 명시했습니다.
- 역할·기술·그룹·연결 설명·동기/비동기 구분을 보존했습니다. 파일 경로·보안 정답은 추가하지 않았습니다.
- 같은 시스템을 다른 시각 표현으로 나타낸 실험입니다. 좌표만 이동한 실험은 아니며 ID 반복과 종류 명시의 효과가 함께 포함됩니다.

**완벽 인식 가정**은 원본 그래프의 모든 구성요소·역할·연결을 구조 JSON으로 직접 전달하는 대조군입니다. 그림을 실제로 완벽하게 읽은 측정값이나 0초짜리 비전 호출이 아닙니다. 후속 코드 검색·Ministral 검토는 다른 방식과 동일하게 실측합니다. 그림 자체에 빠진 백그라운드 작업까지 추가하거나 취약점 정답을 전달하지 않습니다.

실행 순서는 기존 → 개선 → 개선 → 기존(ABBA)입니다. 모델·프롬프트·이미지 크기·생성 한도를 동일하게 유지했습니다. 구성요소/연결 평균은 유효 응답만의 값이며 실패 횟수를 함께 표시합니다. 시간은 실패를 포함한 두 시도입니다. 2회만으로 통계적 유의성이나 모든 아키텍처에 대한 일반 성능을 주장하지 않습니다.

연결 일치는 방향과 양 끝 ID를 대조한 엄격한 지표입니다. 중간 브로커를 생략한 요약도 불일치일 수 있습니다. 역할·보호 수단·법률 준수 정확도는 이 숫자로 평가하지 않습니다. JSON 형식 통과와 구조 정확도는 별개입니다.

## 후속 코드 검색 및 Ministral 검토

유효 응답이 있는 그림은 **첫 번째 유효 응답**을 그대로 사용합니다. 두 번 모두 구조 검증에 실패한 개선 그림은 코드 인덱스로 대체했습니다. 점수가 좋은 응답을 골라 쓰거나 사람이 수정하지 않았습니다. 네 방식 모두 기존 파일 선별기·96개 파일/96,000바이트/3단계 연결 예산과 최대 2회 추가 조회를 사용합니다.

| 방식 | 최초 → 추가조회 파일 | 입력 토큰 | 출력 토큰 | 계획·리뷰 시간(초) | 필수 맥락 / 12 | 원문 근거 / 4 |
|---|---:|---:|---:|---:|---:|---:|
| 코드 인덱스만 | 96 → 97 | 20,185.0 | 2,411.0 | 179.85 | 10 | 0 |
| 기존 그림 (코드로 대체) | 96 → 96 | 19,133.0 | 1,697.0 | 90.89 | 10 | 0 |
| 개선 그림 (코드로 대체) | 96 → 96 | 19,133.0 | 1,697.0 | 91.24 | 10 | 0 |
| 완벽 인식 가정 · 원본 구조 JSON | 96 → 96 | 25,782.0 | 1,437.0 | 109.61 | 9 | 0 |

검토 시간에는 최초 이미지 인식이 포함되지 않습니다. 다음 합계는 첫 유효 이미지 인식·JSON 검증·저장과 계획·리뷰를 더한 값이며 하나의 통합 요청을 잰 시간은 아닙니다.

- **기존 그림**: 맥락 전달 `False`, 선택 사유 `NO_MATCHING_ANCHOR_COMPONENT`, 코드 모듈 매핑 0/27. 첫 사용 합계 155.38초, 입력 23,444·출력 2,980토큰.
- **개선 그림**: 맥락 전달 `False`, 선택 사유 `DISABLED`, 코드 모듈 매핑 0/0. 이미지 기반 첫 사용 합계 없음.
  첫 인식 실패 시도 + 코드 인덱스로 대체한 검토의 비용은 **157.66초**, 입력 **23,444.0토큰**입니다. 인식 실패 비용을 0으로 처리하지 않으며, 성공한 구조 기반 검토 시간으로 해석하지 않습니다.
- **완벽 인식 가정**: 맥락 전달 `True`, 선택 사유 `CACHED_ARCHITECTURE_NEIGHBORS`, 코드 모듈 매핑 24/28. 표의 토큰·시간은 원본 구조 JSON을 포함한 계획·리뷰만의 실측값입니다. 이미지 인식 포함 총시간은 계산하지 않습니다.

### 구조 인식과 코드 매핑의 별도 한계

- **기존 그림**: 추출된 ID 중 실제 서비스 폴더명과 같은 **23개**가 모듈 매핑에서는 연결되지 않았습니다. 현재 선별기는 구성요소 `id` 대신 `label`로 모듈명을 찾습니다. ID와 역할 설명을 분리해 출력한 경우 이 인터페이스 문제가 영향을 줍니다.

완벽 인식 가정 JSON은 구성요소 label에 ID와 역할을 함께 담는 기존 변환기를 사용합니다. 따라서 실제 Qwen 응답과 이 대조군의 차이에는 인식 정확도뿐 아니라 표현 형식과 현재 매핑 구현의 영향도 포함됩니다. 이번 고정 실험 중 선별기 구현은 변경하지 않았습니다.

전체 코드 320개 파일 비교는 [이전 실험](../../RESULTS.md)에 남아 있습니다. 이번 실험에서는 다시 실행하지 않았습니다. 이전 Ministral 비전 결과와 이번 Qwen 결과 사이의 차이를 그림 개선만의 효과로 해석하지 않습니다.

## 응답 호환성 처리와 초기 실패 기록

Ollama 0.32.1의 이 로컬 실행에서는 Qwen의 구조 JSON이 `message.content`가 빈 상태로 `message.thinking`에 담겨 반환됐습니다. 최초 content 전용 실험은 중단하고 [초기 실패 기록](../qwen3-vl-8b/preflight-status.json)과 실행기 스냅샷을 보존했습니다. 최종 실험은 content가 비어 있을 때에만 thinking 필드 전체가 동일한 엄격한 구조 JSON 스키마를 만족하는지 확인합니다. 자유 서술에서 JSON을 추출하거나 내용을 고치지 않습니다. 이 호환성 처리를 양쪽 그림에 동일하게 적용한 새 측정입니다.
