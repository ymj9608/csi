# 읽기 쉬운 아키텍처 설계도와 Qwen 비교

[개선한 PNG](architecture.png) · [확대 가능한 SVG](architecture.svg) · [구성요소/연결 좌표와 해시](architecture.render.json)

같은 합성 시스템을 구성요소 목록과 방향 있는 연결 목록으로 다시 표현했습니다. 기존 28개 구성요소, 26개 연결, 6개 업무 그룹을 보존합니다. 이미지 크기도 기존과 동일한 3000×2320입니다.

**실측 요약:** Qwen 응답 원문의 연결 끝점 일치는 기존 7/26개에서 개선 23/26개로 늘었지만, 개선 응답은 구성요소 5개를 누락해 두 번 모두 구조 검증에 실패했습니다. 원본 구조 JSON을 직접 제공한 완벽 인식 가정의 후속 검토는 25,782 입력 토큰·109.61초였고 필수 파일 9/12개만 확보했습니다. 구조 인식, ID 기반 코드 매핑, 파일 선택 한도, 검토 근거 품질을 분리해 개선해야 합니다.

## 설계 원칙

- 위쪽 목록: 서비스 ID, 역할, 기술, 구성요소 종류, 논리적 그룹을 표시합니다.
- 아래쪽 연결: 한 행에 하나의 시작점 → 도착점만 배치합니다. 선 교차와 여러 화살표가 겹치는 구간이 없습니다.
- 화살표 옆에 정확한 서비스 ID를 반복하고, 연결 설명과 동기/비동기 구분을 표시합니다. 같은 ID는 같은 구성요소입니다.
- 원본 구조에 있던 종류를 명시적으로 적었습니다. 좌표만 변경한 실험은 아니며, 정보 표현·반복 방식 개선을 함께 평가합니다.
- 코드 경로·취약점 정답·추정 암호화 여부는 추가하지 않았습니다. 업무 그룹을 보안 신뢰 경계로 해석하지 않습니다.

이 그림은 연결 정보를 명확하게 읽기 위한 설계 명세입니다. 모든 서비스가 실제로 배포되어 있거나, 모든 백그라운드 경로가 표시되어 있다는 뜻은 아닙니다.

## 비교하는 것

비전 모델은 사용자 지정 **`qwen3-vl:8b`**, 코드 검토 모델은 기존 **`ministral-3:8b-instruct-2512-q4_K_M`**입니다.

1. 같은 Qwen으로 기존 → 개선 → 개선 → 기존 순서로 인식합니다. 이미지마다 2회이며, 생성 설정·프롬프트·이미지 크기를 동일하게 유지합니다.
2. 그림마다 첫 번째 유효 구조 JSON을 선택합니다. 점수가 높은 응답을 골라 쓰지 않습니다.
3. 코드 인덱스만 / 기존 그림 / 개선 그림 / 완벽 인식 가정의 네 방식으로 같은 코드 선별·Ministral 검토를 실행합니다.
4. **완벽 인식 가정**은 그림의 원본 구조 JSON을 직접 제공하는 대조군입니다. 인식 성공률·시간을 실제 비전 측정값으로 표시하지 않으며, 후속 처리만 실측합니다. 그림 밖 코드를 추가하거나 보안 정답을 제공하지 않습니다.

## 응답 호환성

최초 실행에서는 이 로컬 Ollama 0.32.1의 Qwen 응답이 빈 `message.content`와 구조 JSON이 담긴 `message.thinking`을 반환했습니다. content만 읽던 실행을 중단하고 [초기 실패 기록](qwen3-vl-8b/preflight-status.json), 원문 응답, 실행기 스냅샷을 보존했습니다.

최종 실행에서는 content가 비었을 때에만 thinking 전체가 동일한 구조 JSON 스키마를 충족하는지 검증합니다. 자유 서술에서 JSON을 추출하거나 내용을 보정하지 않습니다. 두 그림에 같은 처리 규칙을 적용했습니다. 초기 실패 호출과 모델 다운로드 시간은 최종 실측 표에 합산하지 않습니다.

## 재현

CSI 루트에서 실행합니다.

```bash
# 설계도 재생성: 로컬 Chrome/Playwright 사용
.venv/bin/python scripts/render_readable_architecture.py --render

# 파일과 응답 검증 테스트
.venv/bin/python -m pytest tests/test_readable_architecture.py -q

# 기존 로그 집계: 모델 호출 없음
.venv/bin/python scripts/summarize_readable_architecture.py
```

측정 명령은 `scripts/benchmark_readable_architecture.py --prepare` 다음 `scripts/benchmark_readable_architecture.py`입니다. 기존 프로토콜·로그가 있으면 덮어쓰지 않습니다. 새 측정은 별도 버전 경로를 정해 진행해야 하며, 동결된 그림·코드·선별기를 실행 중에 변경하면 안 됩니다.

현재 실험은 합성 자료에서 구조 인식과 코드 근거 수집을 확인합니다. 수정 패치의 정확도, 서비스 배포, 전체 개인정보보호법 준수를 검증하는 실험은 아닙니다.

설계도 보존·응답 호환성·집계 및 기존 선택기 관련 자동화 테스트는 [검증 기록](../../../testing/readable-architecture-validation.json)에 있습니다. 128개 통과는 소프트웨어 검사 결과이며 AI 인식·보안 판단의 성공률이 아닙니다.
